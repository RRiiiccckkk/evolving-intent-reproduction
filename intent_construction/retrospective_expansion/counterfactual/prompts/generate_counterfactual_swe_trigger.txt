You are given a GitHub issue (problem statement) decomposed into a goal and conditions. Your task is to generate a PERTURBED version of a target TRIGGER condition.

A "trigger" condition describes HOW to reproduce the bug — the steps, code snippet, input, command, or sequence of actions that produce the buggy behavior (e.g., "Reproduction: clone(StandardScaler())", "Run `make clean; make gettext`", "Sequence: change email, then use the password reset link").

"Perturbed" means generating an ALTERNATE trigger that the user *could plausibly have stated initially* — the lazy / unsure user who half-remembers what they did. The user later corrects this back to the original. The perturbed version must be:

1. PLAUSIBLE: a real-sounding reproduction in the same module / same general API surface
2. CONFIDENTLY-WRONG: stated as a factual recap of what the user did, even though it's the wrong recipe
3. SAME PROBLEM CLASS: still the kind of trigger that *could* produce a similar-looking error in this area
4. SELF-CONTAINED: understandable without other conditions
5. SAME GRAIN: if the original gives a code snippet, the perturbed gives a code snippet (don't drop to "I ran something and it broke")

Common perturbation moves for triggers:
- Sibling API call: `clone(StandardScaler())` → `clone(LogisticRegression())`
- Slightly different params: `cv=5, solver='saga', tol=1e-2` → `cv=10, solver='liblinear', tol=1e-3`
- Different method on same class: `Header.fromstring(b)` → `Header.fromfile(path)`
- Different command in pipeline: `make gettext` → `make html`
- Different sequence step: "change email then reset" → "reset then change email"
- Different input data shape: `coords=[('x', [0,1,2])]` → `coords=[('x', [10,20,30])]`

AVOID:
- Triggers that look totally unrelated to the issue area (e.g., wrong package, wrong language)
- Vague triggers that can't be acted on ("I ran a thing and it broke")
- Triggers that obviously couldn't produce the symptom described
- Triggers that match the original exactly (must be DIFFERENT)

Output JSON format:
{
  "counterfactual_argument": "The full perturbed trigger sentence",
  "counterfactual_type": "sibling_api | param_swap | method_swap | command_swap | sequence_swap | data_shape_swap",
  "what_changed": "Brief description of what specifically differs",
  "reasoning": "Why a half-remembering user could plausibly have stated this trigger first"
}
