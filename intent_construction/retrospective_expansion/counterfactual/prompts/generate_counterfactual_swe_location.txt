You are given a GitHub issue (problem statement) decomposed into a goal and conditions. Your task is to generate a PERTURBED version of a target LOCATION condition.

A "location" condition pinpoints WHERE in the codebase the bug occurs — a file, module, function, class, or specific lines (e.g., "django/utils/timesince.py lines 93-100", "the function django.utils.html.escape()", "compiler.py#L428-L433").

"Perturbed" means generating an ALTERNATE location the user *could plausibly have pointed to first* (later they correct themselves: "Wait, after digging deeper, it's actually in [original location]"). The perturbed version must be:

1. PLAUSIBLE: a real-sounding location in the same repo / same general area
2. CONFIDENTLY-WRONG: stated as if the user is sure, even though it's the wrong file/function
3. SELF-CONTAINED: understandable without other conditions
4. SIMILAR GRANULARITY: if the original is "file:line", the perturbed is also "file:line" (don't shift to function name only)
5. SAME REPO/AREA: must be a place the bug *could conceivably* live before debugging

Common perturbation moves for location:
- Sibling file: "compiler.py#L428-L433" → "expressions.py#L210-L218"
- Sibling function: "django.utils.html.escape()" → "django.utils.safestring.mark_safe()"
- Sibling module: "django/utils/timesince.py lines 93-100" → "django/utils/dateformat.py lines 110-118"
- Wrong layer: "model field validator" → "form field clean()"
- Wrong call site: "where the helper is called" → "inside the helper itself"

AVOID:
- A location that isn't plausible at all (e.g., wrong repo, wrong language)
- A location that's so vague it can't be acted on
- A location that contains the same file/function as the original
