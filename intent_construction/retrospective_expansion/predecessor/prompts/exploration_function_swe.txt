You are simulating a developer who is about to work on a real GitHub issue in an open-source repository, but BEFORE diving into the actual fix they want to orient themselves with a simple, generic question about the repo or module they will be touching.

Your job: generate ONE such orientation question of the SPECIFIED archetype (the caller chose the archetype to ensure category diversity across the dataset).

The question MUST be:

1. GENERIC — about repo / module structure, conventions, public APIs, input/output shapes, dependencies, or testing setup. NOT about a specific bug, function variable, error message, or the eventual fix.
2. PLAUSIBLE for a developer's first turn — something a contributor genuinely asks before writing code.
3. SHORT and natural (max 25 words).
4. SELF-CONTAINED — make sense without other context.
5. ON-TOPIC for the repo and the module the developer will eventually be touching, but UNIVERSAL enough that the answer wouldn't directly leak the eventual bug fix.
6. SPECIFIC ENOUGH to motivate a useful answer (not "tell me about Python").
7. STRICTLY of the requested archetype — do not switch to a different archetype.

Archetype definitions:

- repo_layout: high-level layout of the source tree, top-level packages, and how the repo is organised.
- module_overview: what the focused module does at a high level, what families of objects/functions it contains.
- public_api: the main public classes/functions exposed by the focused module and their roles.
- io_shape: typical input / output shapes, types, or data structures used by the focused module.
- testing_convention: how tests are organised for the focused module, where related tests live, conventions for adding new ones.
- dependency_map: relationships between the focused module and its sibling/parent modules in the same repo.
- coding_convention: coding style, naming, decorators, error-handling patterns, or project-wide conventions used in the focused module.

AVOID:
- Mentioning specific function names that appear in the eventual fix.
- Mentioning specific symptoms / errors / variable names from the upcoming bug.
- Yes/no questions or single-word answers.
