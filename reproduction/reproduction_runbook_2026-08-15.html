执行与验收顺序

  1. 静态扫描所有付费调用，确认没有输出 token 上限，模型解析结果只有 kimi-k2.6。
  2. 启动前确认 Modal app、keeper、watcher、本地 evaluation gate 和第二个 5090 owner 均不存在。原 owner 或 construction worker 仍活跃时只观察，不强杀、不删除锁文件、不启动第二批。
  3. Stage 1/2 只读复用；每条 Stage 3 与评测结果原子落盘。owner 全部退出后先用 --inspect-only 验证 task ID、input hash、policy/source hash、完整 gate 与聚合顺序，再按固定 task ID 集合补缺；已提交的非零 Stage 3 不能重置。
  4. Stage 3 的 None、verification rejection 或 independence rejection 都从原 Stage 2 输入整链重生成，总计最多 8 次完整样本尝试（首次加最多 7 次重试）；不复用半条 chain。accounting、模型锁、policy 与系统异常立即失败。
  5. 所有 Python 入口使用仓库 .venv/bin/python -m <module>。付费调用前验证 construction、pipeline、evaluation 的 --help 和 BrowseComp shell 语法，禁止裸 python。
  6. 本次验收边界：BIRD 100/100、SWE 50/50 已完成；BrowseComp+ 为 Stage 3=10/100 且 paired NOT_RUN，不声明正式复现完成。
  7. 因 BrowseComp+ 未达到 complete，本次不执行私密产物拉回；只提交脱敏聚合进度文件。
  8. 生成聚合结果、逐样本状态、usage 账本、未结算 reservation 和模型审计。
  9. 精确暂存候选安全产物后运行 .venv/bin/python -m reproduction.audit_safe_export；Git index 中出现 BrowseComp+ 明文 query、gold document 指纹、实际 CC Switch key 或原始 BrowseComp 结果路径时立即失败。任何后续 git add、报告重生成或 amend 都必须重跑，并另做待推送历史 secret scan。
  10. BrowseComp+ 明文 query、gold documents、完整响应与私密 API key 不上传；只同步代码、脱敏证据、聚合报告和安全 manifest。
  11. 全部测试通过后提交并推送到私有仓库 RRiiiccckkk/evolving-intent-reproduction。
