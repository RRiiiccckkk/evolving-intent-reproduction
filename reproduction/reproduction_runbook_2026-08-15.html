执行与验收顺序

  1. 静态扫描所有付费调用，确认没有输出 token 上限，模型解析结果只有 kimi-k2.6。
  2. 完成每个 benchmark 的 1 个 task ID 无歧义 smoke test；成功后按 published ID 集合扩到全量。
  3. 每条成功结果原子落盘；重启时重新计算 manifest 集合减去 processed task IDs。
  4. paired 两组完成后运行原生 verifier，并断言 BIRD 100/100、BrowseComp+ 100/100、SWE 50/50。
  5. 生成聚合结果、逐样本状态、usage 账本、未结算 reservation 和模型审计。
  6. BrowseComp+ 明文 query 与私密 API key 不上传；只同步代码、加密/脱敏证据、聚合报告和可复查 manifest。
  7. 全部测试通过后提交并推送到私有仓库 RRiiiccckkk/evolving-intent-reproduction。
